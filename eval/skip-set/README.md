# Skip test set

A fixed set of 65 real products, each with a store, a shelf scenario and the verdict a careful friend would give, written down before the verdict engine was run on them.

- `cases.json`: the products (brand, name, category, key attributes, store, the price shown) and the expected verdict, reasons and a one-line why.
- `shelf.json`: the shelf and monthly budgets of **Sam, a fictional shopper**. Nothing in it is anyone's real shelf. A case can patch one shelf item (for example "in this scenario the cleanser lasts until January").
- `price-bands.json`: derived price statistics (typical, low, high, latest) from each product's cleaned 90-day catalogue history. Raw histories are never committed.
- `RESULTS.md`: generated by `npm run eval:skip`. Do not edit by hand.

## How expectations were written

By hand, case by case, from the shelf, budgets, store and price band, before the engine existed. A skip means "don't buy this at all": the shopper already owns something that does the same job and isn't running out. Wait means "not now" (over budget, above its usual price, or the one you have isn't used up yet). Buy means buy now. Ask means the input isn't clear enough to decide.

Where more than one reason fits, `reasons` lists each acceptable one. Only the verdict counts towards the headline; reasons are reported separately.

## What is scored

- Skip correctness: for each case, did the engine skip exactly when the expectation says skip? Reported as correct / N, with precision and recall of skip.
- The full list of wrong skips (skipped when it shouldn't) and missed skips (should have skipped).
- Overall verdict agreement and reason agreement.

The engine reads only the structured fields in these files. No model or network call is made when scoring.
